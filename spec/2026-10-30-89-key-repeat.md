# Spec: one key press is one key, however slow the desktop

## Design

**A key tap becomes one helper line, `P`, which presses and releases its keys
in a single flush.**

- **Helper** (`src/ai_mirror_input/ai_mirror_input.c`): a new command
  `P <code> [<code> ...]`, 1-5 evdev codes. It presses the codes in order and
  releases them in reverse, with one timestamp. Each event updates
  `key_state` and `keys_down` and sends the modifiers, exactly as `K` does,
  so a chord such as `CTRL+C` carries its modifier. Then one flush, one round
  trip, one `OK`. A bad code answers `ERR bad key` before anything is sent.
  The header's command list gains the line.
- **Encoder** (`src/ai_mirror/input.py`): a `key` action emits
  `P c1 ... cn` instead of n `K 1` lines and n `K 0` lines. A newline or tab
  inside `type` emits `P 28` / `P 15`. `key_down`, `key_up` and the
  `modifiers` field around other actions stay `K` lines: they are holds the
  agent asked for.
- **`run_batch`** (`src/ai_mirror/control.py`): unchanged. It still checks
  ownership and the target before every line, which is now before every
  tap. It tracks held keys only from `K ` and `B ` lines, and a `P` line
  leaves nothing held, so its `pressed` set and the #68 key-up rescue stay
  correct without edits.

The press and release now reach the compositor in the same flush, so no
client sees the key held, whatever the per-line checks cost.

## Alternatives rejected

- **Skip the per-line checks for release lines.** It weakens the invariant
  that ownership is checked before every helper line, and on a slow desktop
  the round trip alone still costs about 350 ms.
- **Turn key repeat off for the virtual keyboard** with a Hyprland `device`
  rule. That is host configuration rather than ai-mirror, it needs the
  device's name, and it would also hide repeats an agent asked for with
  `key_down`.
- **Send release timestamps equal to the press.** Clients time repeat on
  their own clock, not on event timestamps. The helper already sends equal
  timestamps inside `T`.

## Risks

- **Delivered and total counts change.** A `key` action is now one line
  instead of 2n. Refusals report `delivered`/`of` in lines and in actions
  (#30). Action counts are unchanged; line counts get smaller. Tests that
  pin line lists change with it.
- **Chords that open a surface.** Today `SUPER+SPACE` can be refused halfway
  (the menu opens between the press and the release, and the release is
  then refused, as measured in the #1513 tests). With `P` the whole tap
  lands before the next check. That is the intended behaviour: the key is
  never left half-pressed. The next action is still refused if the new
  surface is in the way.
- **Hosts:** every host running ai-mirror, after a lock bump. There is no
  persisted state.

## Verification

1. `python3 -m unittest discover -s tests` with updated expectations, plus
   new cases: `key` with a chord gives one `P` line in press order; a
   newline inside `type` gives `P 28`; `key_down`/`key_up` still give `K`.
   Also `nix build .#ai-mirror-input` and `nix flake check`.
2. In a `nixarchy-desktop` microvm through MCP, with the helper swapped in
   by a wrapper copy: `WAYLAND_DEBUG=client foot` shows each `key RETURN` as
   one press and one release within the same millisecond, and no extra
   prompts appear.
3. The #88 matrix (foot, alacritty and kitty, five checks each, plus `é€`)
   still passes 5/5, 5/5, 5/5 and 3/3.
