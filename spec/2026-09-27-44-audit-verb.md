# Spec: `ai-mirror audit`

## The vocabulary, read rather than invented

Five events are written, all from `control.py`:

| event | fields beyond `event` and `at` |
|---|---|
| `requested` | `request`, `by`, `holder` |
| `confirmed` | `request`, `by`, plus what `confirm_request` adds |
| `denied` | same shape as `confirmed` |
| `expired` | `request`, `by` |
| `off` | `by`, `was`, `holder` |
| `idle` | `by`, `holder` |

`audit()` writes `json.dumps({'event', 'at', **fields}, sort_keys=True)`, one
per line, appended at `0600` under `root()` — `$XDG_RUNTIME_DIR/ai-mirror`,
created on every call. `at` is `stamp()`, `%Y-%m-%dT%H:%M:%S%z`.

That the directory is always created and the file is not is what makes "no
file" a clean answer rather than an error: it means nothing has been recorded
**this boot**.

## The open questions, settled

**Q1 — CLI only. No MCP tool.** AGENTS.md's recipe is "`api.run` branch +
`mcp.TOOLS` entry + CLI subcommand + test", and this departs from it
deliberately. The reader this exists for is a person deciding whether to trust
what an agent did; offering the agent its own trail is a different feature
with a different argument, and AGENTS.md's own invariant — *"Do not add
machinery claiming more"* — cuts against surfacing a trust artifact to the
party being trusted.

It still gets an `api.run` branch, because that is where the logic belongs and
what the tests drive. It simply gets no `mcp.SPECS` entry. **AGENTS.md gains a
sentence** saying the recipe has one exception and why, so the next reader
does not file the gap as an oversight — which is the same failure mode #43
just fixed one level up.

**Q2 — the last 20 by default, `-n` to change it, `-n 0` for everything.**
Per-boot bounds the file, but a long session is still thousands of lines and
the question people ask is "what just happened".

**Q3 — human-readable by default, `--json` for the raw lines.** "JSON in/out"
is the house style for the MCP surface, which this is not part of. A verb
whose whole point is that somebody reads it should not need `jq`. `--json`
passes the lines through unchanged so a program keeps the real thing.

**Q4 — yes, `status` names it.** A reader asking "what happened" tries
`status` first. One field in its output pointing at `audit` is the difference
between discoverable and merely present.

## Design

### `api.run('audit', {...})`

Returns a dict, because everything in `api.run` does:

    {'entries': [...], 'since': '<ISO stamp>', 'source': 'file'|'absent', 'total': N}

- `entries` — parsed lines, newest last, at most `n`
- `source` — `absent` when the file does not exist. **This is the whole
  second half of the intent**: an empty `entries` with `source: absent` means
  nothing recorded since boot, and the caller must be able to tell that from
  a log that exists and happens to be empty.
- `since` — when the log begins. The file's `st_mtime` of the first line is
  not available, so this is the boot time, from `/proc/stat`'s `btime`, which
  is stdlib and needs no dependency. Stated so "nothing since 09:14" is never
  read as "nothing, ever".

A malformed line is skipped and counted, not fatal. The log is append-only
from one writer, so a partial line means a crash mid-write; refusing to show
the other 400 entries because of it would be the wrong trade for a tool
someone reaches for when worried.

### `ai-mirror audit [-n N] [--json]`

Prints one line per entry, newest last:

    2026-09-27T06:12:04+0100  requested  by=agent holder=31142
    2026-09-27T06:12:09+0100  confirmed  by=agent
    2026-09-27T06:22:09+0100  idle       by=agent holder=31142

and, when there is nothing:

    no control events recorded since this machine booted at 2026-09-27T05:40:11+0100
    ($XDG_RUNTIME_DIR does not survive a reboot, so this is not a record of
    everything that has ever happened on this machine)

The parenthetical is the point. An empty answer that does not say why it is
empty is a false all-clear.

### Read-only, structurally

No write path, no clear, no rotate, no `--since` that could be mistaken for
one. The intent's constraint: a log an agent can truncate is worse than no
log, because it reads as evidence.

### Remote

Nothing special. It reads a file and prints to stdout, so
`ssh desk ai-mirror audit` works the day it lands — which is the reason the
issue exists, and the reason nixarchy did not wrap it.

## Alternatives rejected

**An MCP tool as well.** Q1 above. Reversible: adding one later is an entry in
`mcp.SPECS`, and nothing in this design forecloses it.

**JSON by default.** Matches the house style for the wrong surface, and makes
the common case need `jq`.

**Reading the bar widget's state instead.** The widget shows *now*; the log
shows *what happened*. Different question.

**Inferring "since" from the file's mtime.** It is the time of the *last*
write, not the first. Boot time is the honest answer and `/proc/stat` has it.

**Filtering by event type.** Speculative. The whole file is small enough that
`| grep` covers it, and a `--event` flag is easy to add when someone wants it.

## Risks

- **`/proc/stat` is Linux-only.** So is everything else here — this drives
  Hyprland — but it is a new assumption in a module that did not have one.
  A missing `btime` degrades to omitting `since`, never to failing.
- **Printing an audit trail could itself be sensitive.** The fields are ids,
  pids and event names, not content; nothing from the desktop is in there.
  Worth stating so nobody adds a field later that changes that.
- **The "no entries" wording is the deliverable and no test can read English.**
  A test can assert `source == 'absent'`; it cannot assert the sentence is
  clear. Same class of risk as nixarchy#1018's documentation.
- **Departing from AGENTS.md's recipe invites a future PR "completing" it**
  by adding the MCP tool. Mitigated by the sentence in AGENTS.md, which is the
  only durable form of the argument.

## Verification

`tests/` cannot reach the desktop and does not need to — this is a read, and
AGENTS.md notes reads are deliberately unguarded.

| what | how | break it by |
|---|---|---|
| entries come back parsed and newest-last | write three known lines into a temp `root()`, assert order and fields | reversing the slice |
| **`absent` is distinguished from empty** | one case with no file, one with a zero-byte file; assert `source` differs | collapsing both to "no entries" |
| a malformed line is skipped, not fatal | a good line, a truncated line, a good line; assert two entries and a count | letting `json.loads` raise |
| `-n` bounds the output and `-n 0` does not | 50 lines, assert 20 by default | off-by-one on the slice |
| the CLI prints something a person can read | assert the human format for one entry, not the whole rendering | — |
| **no MCP tool is exposed** | assert `'audit' not in mcp.SPECS` | adding it, which must fail this test and make somebody read Q1 |
| `status` names the verb | assert the field is present | removing it |

That sixth row is the one worth having: it turns a deliberate omission into a
decision a future change has to argue with, rather than a gap somebody quietly
fills.

## Open questions

1. **Does `-n 0` mean "everything" or "nothing"?** `0` as unbounded is a
   convention, and it is also the answer a script passes by accident when a
   variable is empty. `--all` is unambiguous and one more flag.
2. **Should `status` embed the last event, or only name the verb?** Embedding
   makes the common case one command; it also puts a slice of the trail in
   every `status` call, including the MCP one, which is Q1 in through a side
   door.
