# Spec: a default that cannot reach your desktop

**Revised after approval.** The first version was built on a claim in #15 that
turned out to be false — that this repository had no development environment.
`flake.nix:138` defines a complete `devShells.default`, and `nix develop -c
python3 -m unittest discover -s tests` runs the suite green today. The
`devenv.nix` that version proposed would have duplicated a working environment
and pulled a second nixpkgs to do it, so it is gone, and with it the
`nixosTest`. What is left is the part of #15 that was always true.

## The intent's open questions, answered

1. **The split is not by speed. The local default stops being able to touch the
   desktop at all.** Twice a test has been one forgotten stub away from the
   developer's own session — #12's control gate, and 584d8ee before it — and
   both were caught by a person reading a diff. A third will not be. The
   side-effecting seams refuse to act while the suite runs, so a forgotten stub
   becomes a **test error** rather than a write to somebody's desktop.
2. **No VM for the automated suite, and no `nixosTest`.** The compositor-backed
   test was the most speculative part of the first version and nothing depended
   on it; it is dropped rather than carried as a maybe. `nix run .#vm` headless
   is used **interactively**, for the one measurement that needs a quiet
   machine. This repository owns no VM's lifecycle.
3. **Nothing crosses into a VM.** That question only existed to serve the
   `nixosTest`.
4. **#12 step 7's measurement is now in scope** — reversed. It is the concrete
   thing that failed, the VM is the reason it can now succeed, and leaving it
   out would mean shipping the enabler and not the thing it enables.

## Design

### 1. Say that `nix develop` is the environment

The real gap behind #15's first problem is not a missing environment but a
silent one: nothing in `README.md` or `AGENTS.md` mentions `nix develop`, so the
way to find it is to read `flake.nix`. A contributor should be told, once, what
the shell is and what it carries — `python` with pygobject, `GI_TYPELIB_PATH`,
`WLR_PROTO`, and the C helper's build inputs — and that
`nix develop -c python3 -m unittest discover -s tests` is the loop.

No new environment file. The devShell already exists and already works.

### 2. A guard at the seams that reach the human

One module-level switch, off by default, which the test base class turns on.
While it is on, the calls that change the world outside the process raise
instead of acting:

- `a11y.set_bus_property` (`a11y.py`) — writes `org.a11y.Status`;
- `control.Helper.start` and `.cmd` (`control.py:272`, `:288`) — the virtual
  keyboard and pointer;
- `host.ctl` with `dispatch` (`host.py:10`) — moves the human's windows.

Reads are deliberately left alone. `hyprctl -j clients` and an AT-SPI walk
observe without disturbing, `index.nav()`'s `enable=False` read is exactly the
shape that should stay allowed, and guarding them would force a mock in front of
every harmless query in the suite.

The raised message names the seam and says what to stub, because the failure's
whole value is telling the next person what #12 took a review to notice. Turning
it off for a test that genuinely wants a live seam must be one obvious line, not
a ritual — an awkward switch gets disabled globally and we are back where we
started.

### 3. Finish #12 step 7, in `nix run .#vm`

`QEMU_OPTS="-display none -serial mon:stdio" nix run .#vm`, ssh on 2222. A clean
nixarchy that nobody is using, where the set of running applications is chosen
rather than whatever happened to be open.

That is precisely what the failed measurement lacked. On the host it was taken
against Chrome sitting near 72% of a core with video playing, and two paired 40 s
rounds disagreed — round one showed a cost, round two with the order reversed
did not. It was also mistargeted: Chrome and Discord do not honour
`ScreenReaderEnabled`, so they were the wrong processes to measure for its cost.

In the VM the measurement is: launch applications known to honour AT-SPI, idle,
and compare CPU with the property off and on, per PID and counting only PIDs
alive at both ends — the naive sum over `pgrep` output reported **-147 s of CPU
over 30 s** on the host, because Chrome's renderer set changes between samples.

The outcome is a number in #12's plan, replacing the paragraph that currently
says the cost is unmeasured and that decision 2's justification is unsupported.
Whatever it shows.

## Alternatives rejected

- **A `devenv.nix`.** What #15 asked for, and what the first version of this
  spec specified. `nix develop` already gives the same environment; devenv's one
  advantage over it is activation on `cd`, which needs
  `programs.nixarchy.services.devenv` enabled — a rebuild on a host carrying
  four CI runners, explicitly out of scope. It would leave two environment
  definitions to keep in step and a second nixpkgs drifting from the flake's.
- **Replacing the devShell with devenv.** One environment rather than two, and
  it would split the dev path from `checks.unittest` (`flake.nix:110`) and the
  package build, which share the flake's python today.
- **A `nixosTest` with headless Hyprland.** Unproven for 0.56 under software
  rendering; aquamarine has a headless backend and nixpkgs tests Sway this way,
  but neither is proof. Recorded rather than dropped silently: it remains the
  right answer for the virtual-input and confirm-dialog cases, which stay
  uncovered.
- **Split local from VM by speed, stubbing by hand as now.** Leaves the third
  near-miss to whoever reviews it.
- **Guard every seam, reads included.** Safer on paper, and the cost lands on
  every future test for calls that cannot damage anything.

## Risks

- **A guard can fail wrongly.** Someone exercising a real seam locally now has
  to turn it off. If that is awkward they will disable it globally, and the
  guard becomes theatre.
- **The guard only covers what it is pointed at.** A new side-effecting seam is
  unguarded until someone remembers. It narrows the hole; it does not close it.
- **The VM may not reproduce the host's a11y behaviour.** A clean nixarchy has a
  different application set, and the one application observed to honour
  `ScreenReaderEnabled` on this host was a Spotify client that will not be
  there. If nothing in the VM honours the property, the measurement answers a
  different question and must say so rather than report a zero.
- **The measurement may again show nothing.** That is a permitted outcome, not a
  failure, and #12's plan already records the honest version.
- **Virtual input and the confirm dialog stay untested**, by this spec's own
  choice. Worth stating plainly so it is a known gap rather than an assumed
  cover.
- p620 carries all four nixarchy CI runners. Nothing here rebuilds the machine;
  running a VM is not a rebuild, but it is not free either.

## Verification

**The guard, proven by deliberate sabotage.** Remove the `busctl` stub from the
test base class and run the suite: it must **fail**, naming the seam, and
`busctl --user get-property org.a11y.Bus /org/a11y/bus org.a11y.Status
ScreenReaderEnabled` must read the same before and after. That is #12's
near-miss reproduced on purpose; a guard that cannot demonstrate it is not doing
anything. `git checkout` puts the stub back.

**Nothing regressed.** `nix flake check` green, and
`nix develop -c python3 -m unittest discover -s tests` green.

**The documentation is true.** The commands written down are run as written, from
a clean checkout, and do what the text claims.

**The measurement.** A number, per PID, from a VM whose running applications are
listed alongside it, with the property's state confirmed by `busctl` before and
after each round — and #12's plan updated to match, including if it still shows
no measurable cost.

**Not verified here.** Anything requiring a real compositor: the virtual-input
helper, #11's confirm dialog, the kill switch. Those need the `nixosTest` this
spec rejected, and they remain uncovered.
