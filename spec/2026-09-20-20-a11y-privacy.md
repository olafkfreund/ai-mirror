# Spec: prune the window, keep the fact, never the name

## The intent's open questions, answered

1. **Keep the frame node, drop its name, mark it withheld, and do not
   descend.** Dropping the node entirely hides that a window exists and
   reintroduces the absent-versus-unavailable confusion #18 fixed. Keeping the
   name exposes the sensitive part — frame names here carry an inbox count and
   an email address. Keeping the node *without* its name satisfies both: the
   caller learns a window is there and was withheld, and learns nothing about
   it beyond a category, which is exactly the disclosure #19 already makes.
2. **Yes, `find` says so.** #18 made an empty find explain itself; a find that
   is empty *because* something was withheld is a different and more important
   sentence, and without it this reintroduces the very confusion #18 removed.
3. **Both levels.** An application whose own name matches — `1Password`,
   `gcr-prompter` — is pruned whole. A frame whose name matches inside an
   ordinary application — a bank in Chrome — is pruned alone. One without the
   other is either an outage or a hole.
4. **`a11y_act` re-checks at resolve time.** `resolve()` already walks the index
   path from the desktop, so the check rides along. Without it the guard is
   bypassable with an id obtained a moment before a window became sensitive,
   which is a small window and a real one.
5. **`index.nav()` needs no special handling.** It calls `tree(None, 1, 200,
   enable=False)` and therefore inherits the frame guard. What it reports — which
   applications expose a tree — is a list of running applications, which
   `windows` already returns.

## Design

### 1. The guard rides on the walk, at depths 0 and 1 only

`_walk` yields `(node_id, acc, level, Atspi)`. The check needs an application
name at depth 0 and a frame name at depth 1, and `privacy.kind()` from #19 takes
exactly that pair: measured, an application node's `name` plays the part of a
window class and a frame's `name` plays the part of a title, and the matcher
returns the right category for a password manager, a banking title and a
credential prompt without modification.

**Cost, measured:** 11 applications and 16 frames against a walk yielding 154
nodes — 27 extra `get_name` calls, where `_node()` already fetches name, states,
bounds, actions and text for every node. Under 5%, and nothing at the depths
where the node count lives.

### 2. What a refused window looks like

The frame is yielded with **no name** and a `withheld` field carrying the
category, and its children are not walked. So:

```
{"id": "6.3", "role": "frame", "withheld": "a banking or payment page"}
```

A pruned application is the same shape at depth 0.

### 3. `find` reports that something was withheld

`find` already returns coverage from #18. It gains a count of withheld windows,
and when it withheld anything its note says so — because "no match" and "no
match, and one window was not looked at" are different facts and the second is
the one that changes what an agent does next.

### 4. `act` re-checks on resolve

`resolve()` walks the index path from the desktop. On the way it applies the
same check at depths 0 and 1 and raises rather than returning an accessible
inside a refused window.

### 5. `gotchas.md` gains one sentence

It already documents #19's capture refusal. A reader who learns captures are
refused and not that trees are would reasonably reach for `a11y_find` as the way
round, which is the opposite of what should happen.

## Alternatives rejected

- **Prune the whole application.** What the issue guessed. One `Google Chrome`
  application node carries a frame per window — six here — so one banking tab
  would remove every Chrome window from the tree. A guard that costs the caller
  everything is one they will turn off.
- **Drop refused frames entirely.** Smaller output, and the caller cannot tell a
  withheld window from a window that is not there. #18 exists because that
  distinction matters.
- **Keep the frame name and only prune children.** The name is the sensitive
  part. This would refuse the contents of a bank window while announcing that a
  bank window is open, with its title.
- **Check every node rather than frames.** Thorough and it multiplies the walk's
  cost by a per-node round trip, on a walk that is already thousands of
  synchronous calls.
- **Filter in `tree`/`find` after the walk.** Simpler, and the children have
  already been visited and their text already read by then. The point is not to
  read it.

## Risks

- **The category is itself a disclosure.** `withheld: "a banking or payment
  page"` says a bank window is open. It is the same disclosure #19 already
  makes, and the alternative — an unexplained gap — is the failure #18 fixed.
  Stated so the trade is visible rather than implied.
- **A generic application name will not match.** Discord reports `electron` on
  this desktop. The same heuristic limit as #19 and stated the same way: this
  misses things.
- **An id captured before a window became sensitive.** Closed by answer 4,
  within the resolve path; an accessible held across the transition by some
  other route is not covered.
- **`index.nav()` inherits the change.** Intended, and it means an orientation
  call now reports a withheld frame where it used to report a named one. Worth
  checking it still reads sensibly.
- **`VISIT_CAP` interacts.** Pruning lowers the visited count, so a tree that
  previously truncated may now complete. A behaviour change, and a benign one.

## Verification

**The matcher** is #19's and already tested; this adds only the AT-SPI mapping —
that an application name and a frame name feed it correctly.

**The walk, on a fabricated tree.** A sensitive frame is not descended, comes
back without its name, and carries the category. **Its sibling frames in the
same application are still walked in full** — that is the Chrome case and the
single most important test here, because getting it wrong is an outage rather
than a leak.

**`find`** reports a withheld count, and says so in its note when it withheld
anything, distinguishably from #18's "the desktop exposes nothing".

**`act`** raises for an id inside a refused window.

**Nothing regressed.** The full suite green, `nix flake check` green, and
`index.nav()` still returns a usable orientation.

**Not verified here.** Behaviour against a real password manager's live
accessibility tree. 1Password is installed but was not running, and its AT-SPI
application name is assumed to contain "1Password" rather than observed.
