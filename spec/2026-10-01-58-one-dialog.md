# Spec: One confirm dialog, however many bars

Stacked on `fix/48-dialog-stray-key`. It moves #48's dialog unchanged.

## What the installed shell does (checked, not assumed)

Against `nixarchy-omarchy-tree` (`rp5i87d4…`), the shell this host runs:

- **The overlay is loaded exactly once.** `shell/shell.qml:1301-1330`,
  `computePanelEntries` plus an `Instantiator`, creates one `Loader` per
  enabled plugin whose `kinds` include `overlay`. The loader is active when
  `keepLoaded` is true, which our manifest already sets.
- **Enabled already.** An overlay-capable plugin counts as enabled through
  its existing `bar.layout` entry, as omapilot's `Ambient.qml:53-58`
  documents.
- **What the loader injects:** `omarchyPath`, `shell`, `manifest` and
  `pluginRegistry` (`shell.qml:1335+`), but not bar-widget `settings`. The
  dialog uses none of these.
- **The validator:** `bin/omarchy-plugin-validate:96-105` requires
  `entryPoints.overlay` whenever `kinds` contains `overlay`. `nix flake
  check`'s plugin check mirrors the validator's other rules, and this spec
  adds that one to it.
- **One side effect:** a plugin that is both a bar widget and an overlay
  stops being treated as a bar-widget panel for the shell's `summon` IPC
  (`shell.qml:1141-1152`). ai-mirror never uses `summon`: grep finds only an
  unrelated regex in `index.py:251`.

## Design

1. **`plugin/manifest.json`:**
   - `"kinds": ["bar-widget", "overlay"]`;
   - `"entryPoints": {"barWidget": "Widget.qml", "overlay": "Overlay.qml"}`.

   Everything else stays as it is, including `keepLoaded: true`.
2. **`plugin/Overlay.qml` (new): the one owner of the dialog.**
   - A `FileView` on `$XDG_RUNTIME_DIR/ai-mirror/state.json`, parsed exactly
     as `Widget.qml:51-60` does, with the same `catch → null`.
   - An `AgentCommand`.
   - `AgentConfirmDialog { request: pending ? state.request : null;
     command: … }`.

   It has no bar presence and no settings.
3. **`plugin/Widget.qml`:** delete the `AgentConfirmDialog { … }` block
   (`Widget.qml:31-34`). The widget keeps its mark, tooltip, click-to-ask
   and stop on every bar. Its own `AgentCommand` stays, for that click.
4. **`AgentConfirmDialog.qml`:** unchanged. #48's rule, the per-request
   reset, the grace timer and pointer arming all move with it.
5. **`flake.nix` plugin check:** add the validator's kind→entry-point rule
   for `overlay`: `jq -e '(.kinds|index("overlay")) == null or
   (.entryPoints|has("overlay"))'`. It fails if someone drops one half.
6. **Docs:**
   - AGENTS.md code map: `Overlay.qml` owns the dialog, and `Widget.qml` no
     longer does.
   - A plugin-section note that the dialog is one per shell.

## Alternatives rejected

- **(b) Only the primary bar's widget creates the dialog.** It needs a rule
  for "which bar", which breaks when that monitor is unplugged or reordered.
  It also keeps the dialog's existence tied to bar count. Rejected in the
  intent.
- **A singleton QML object shared across the widget instances.** That needs
  a `qmldir` singleton registration in a plugin directory the shell loads
  by path. It's more machinery than the shell's own overlay kind, which
  exists for this.
- **Deduplicating answers instead,** e.g. ignoring a second `control
  confirm`. That treats the symptom: three dialogs still grab the keyboard
  and split the pointer and key state.

## Risks

- **The overlay loads `asynchronously: true`** (`shell.qml:1330`). A request
  pending at shell start shows the dialog a moment later than a bar widget
  would. Harmless: #48's grace starts from the request-id change the dialog
  sees.
- **A shell without the `overlay` kind** (an older Omarchy) would ignore the
  entry point and show no dialog at all. Then requests could only be
  answered from the CLI, and would lapse otherwise. This host's shell
  supports it. AGENTS.md notes the minimum, and the README's requirements
  say Omarchy Quattro's plugin architecture, which has it.
- **Two copies of the state watcher**, one in the widget and one in the
  overlay. Each is a cheap file watch. Merging them would need cross-
  component wiring that isn't worth it.

## Verification

- `nix flake check` is green, including the new overlay rule.
- `omarchy-plugin-validate` on the built plugin passes.
- `tests/test_confirm_wiring.py` gains two assertions: `Widget.qml`
  contains no `AgentConfirmDialog`, and `Overlay.qml` contains exactly one.
- **Live (with #48 and #57):**
  - While one request is pending, `hyprctl layers` shows **exactly one**
    `omarchy-ai-mirror-confirm` layer on this three-monitor host. Before
    this change there were three.
  - Quickshell's log shows one open and one close per request.
  - #57's audit shows one answer per request.
