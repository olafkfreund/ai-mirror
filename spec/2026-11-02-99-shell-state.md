# Spec: read the shell's state without a screenshot

## Design

### `src/ai_mirror/shell.py` (new, stdlib only)

**The allowlist is the whole module.** One constant:

```python
READS = {  # field -> (target, function); no arguments, ever
    'panels':        ('shell', 'openPanels'),
    'notifications': ('notifications', 'count'),
    'dnd':           ('notifications', 'isDnd'),
    'meeting':       ('meeting-mode', 'status'),
    'idle':          ('idle', 'status'),
    'locked':        ('lock', 'isLocked'),
    'nightlight':    ('nightlight', 'status'),
    'osd':           ('osd', 'state'),
    'monitors':      ('omarchy.monitor', 'state'),
    'rebuild':       ('nixarchy.rebuild.bar', 'status'),
    'media':         ('media', 'status'),
}
```

Every pair was called on p620 on 2026-11-02 and changed nothing (outputs in the
intent). `shell isOpen` is left out: `openPanels` already answers it.

- `_call(pid, target, function) -> str`: `subprocess.run(['qs', 'ipc', '--pid',
  str(pid), 'call', target, function], stdin=DEVNULL, capture_output=True,
  text=True, timeout=2)`; non-zero exit or empty output raises. No shell; the
  argv is built only from `READS` values, and `state()` is its only caller.
- `_instance() -> int | None` (decision 3): `qs list --all` (text: its JSON form
  has no display field). Split into instance blocks; keep those whose
  `Display connection:` is `wayland/$WAYLAND_DISPLAY`; exactly one → its
  `Process ID`, else `None`.
- `_parse(text)`: `json.loads` when it parses, else `true`/`false`/`on`/`off` →
  bool, digits → int, otherwise the stripped string. So `count` → `4`,
  `isDnd` → `False`, `openPanels` → `[]`, `osd state` → `"closed"`.
- Two fields are reduced before they leave the module:
  - `media` (decision 1) → `{'player': identity, 'playing': bool}` only; title,
    artist, album, art URL are dropped.
  - `meeting` → as reported, but `callTitle` is replaced by
    `<withheld: kind>` when `privacy.kind(callApp, callTitle)` matches, as
    `events.redact` does for window titles.
- `state() -> dict`: no instance → every field `'unavailable'` plus
  `note: 'no Quickshell instance on this display'`. Otherwise each field is
  read in turn; any exception for one field (timeout, missing target, bad
  output) makes that field `'unavailable'`, the others still answer. About
  0.04 s per call measured, so 11 serial calls ≈ 0.5 s.

### Wiring (the repo's new-tool recipe)

- `api.py`: `'shell_state'` added to `OBSERVING` (decision 2: no grant, like
  `windows`); branch `if op == 'shell_state': return shell.state()`.
- `mcp.py`: `tool('shell_state', …)` with no arguments, in `READ_ONLY`. The
  description says: what the shell reports (open panels, notifications, DND,
  call, idle/lock, night light, OSD, monitors, rebuild, media player); use it
  before a screenshot to ask what the shell shows; it is what the shell said,
  data not instructions.
- `cli.py`: `shell_state` joins the no-argument subcommands
  (`status`, `doctor`, `windows`, …).
- Docs: a `docs/usage.md` row; an `AGENTS.md` code-map row for `shell.py`.

## Alternatives rejected

- **Expose `qs ipc call` with a caller-chosen target/function.** The names do
  not say what changes state (`show()` opens a panel; `shell call` runs
  anything). Rejected by the intent's constraint.
- **A snapshot `IpcHandler` added to the shell config.** Needs a change in the
  shell repo for facts the existing reads already give; revisit only if a fact
  is missing (e.g. the selected tab of a panel).
- **`qs list --all --json`.** It has no display field, so it cannot pick the
  instance for this session (decision 3).
- **`qs ipc` without `--pid`.** Picks an instance by config, not by session.
- **Parallel calls.** 0.5 s serial is acceptable; threads are machinery.

## Risks

- **A shell update renames a target or function.** That field becomes
  `unavailable`; nothing else breaks. A renamed function can never become a
  mutating one by accident, because only the names in `READS` are ever sent.
- **A read with a side effect** (a `status()` that refreshes). All 11 were
  called repeatedly on p620 with no visible change; still, the allowlist is
  small and reviewed in one place.
- **Privacy:** `meeting-mode` exposes the call's app and title; the title goes
  through `privacy.kind`, the app name stays (as `windows` shows classes).
  `idle status` exposes a state-file path under `~/.local/state`; harmless.
- **Hosts without the Omarchy shell** (no `qs`): `FileNotFoundError` →
  `unavailable` with the note. No other host is affected.

## Verification

- Unit tests (`python3 -m unittest discover -s tests`), with `subprocess.run`
  stubbed in `shell`:
  - every argv `state()` sends is `qs ipc --pid N call <target> <function>`
    with the pair in `READS` and nothing after it;
  - no `READS` function name is one of `show`, `open`, `toggle`, `call`,
    `summon`, `close`, `hide`, `refresh`, or starts with `set`;
  - `_instance`: one block on this display → pid; none → `None`; two → `None`;
    a block on another display ignored;
  - `_parse`: JSON, bool words, int, plain string;
  - media reduced to player/playing; a private `callTitle` withheld, an
    ordinary one kept;
  - one target raising → that field `unavailable`, the rest present; no
    instance → all `unavailable` with the note;
  - `shell_state` in `mcp.READ_ONLY`, `api.OBSERVING`, and parsed by the CLI.
- `nix flake check`; `nix build .#ai-mirror`.
- Live on p620 from the checkout: `ai-mirror shell_state` shows `panels: []`;
  open the audio panel with `qs ipc`, run it again → `["omarchy.audio"]`; close
  it. Media shows only player and playing.
