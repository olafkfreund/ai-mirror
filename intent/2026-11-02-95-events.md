# Intent: let the agent see what happened between calls

## Problem

ai-mirror reads Hyprland only by asking it (`hyprctl … -j`), and only when
a tool is called. Whatever happens between two calls is lost:

- a dialog or window that opens and closes again (a crash, an error popup);
- focus moving away and back (a notification, another app stealing focus);
- a panel, menu or launcher (a layer surface) that maps and unmaps;
- an urgent window, a workspace or monitor change, a title change.

The agent therefore cannot answer "what did my last action cause?" or
"did anything else happen while I was thinking?" without a screenshot,
and a screenshot shows only the moment it is taken.

The same gap weakens a safety check. `_refuse_new_surfaces`
(`control.py:719`) decides whether something has opened over the target
by comparing layer lists at the moments a window-addressed key is sent;
a surface that leaves and returns between two checks goes unseen
(`gotchas.md:212`).

Hyprland already publishes all of this. Measured on p620 (Hyprland 0.56,
2026-11-02): its event socket (`.socket2.sock`) streams one line per
change — two workspace switches gave 14 events (`workspacev2`,
`activewindowv2`, `createworkspacev2`, …), and opening and closing the
Quickshell audio panel gave `openlayer` / `closelayer` with the namespace.
ai-mirror never reads it.

## Proposed outcome

- An agent can ask "what happened since <cursor>?" and get an ordered list
  of desktop events (windows, layers, focus, workspaces, monitors, urgent),
  each with a sequence number and time, and a new cursor.
- If events were dropped (buffer overflow, Hyprland restart, socket lost),
  the answer says so, rather than looking complete.
- `input` (and possibly `window`, `launch`) can say what changed while the
  action ran, so the agent sees "a panel opened" without a screenshot.
- `wait` keeps polling for states that already hold; events add to it,
  they do not replace it (a state that already holds sends no event).

## Affected users and systems

- ai-mirror: a new module and tool; `mcp.py` server startup; possibly
  `control.py` (surface check) and `api.py` (`input` result).
- Hyprland: read-only use of its event socket. No plugin, no config change.
- The human at the desk: their window titles and focus history become
  something an agent can read after the fact.

## Constraints

- Read-only. Nothing here changes the desktop; no new path to input.
- Window titles are private: titles of windows `privacy.kind` matches
  (password managers, banking, OTP …) are withheld before they are stored,
  not only when read.
- Nothing is written to disk; the buffer is memory-only and bounded.
- Survives a Hyprland restart (instance signature changes, `host.resolve`).
- Stdlib Python, no new dependency. Tests cannot reach the desktop.
- Event text is data, never instructions (same rule as titles today).

## Open questions

1. **When is it recording?** Options: (a) only while this server's agent
   holds control, cleared on `control off`; (b) from server start, so an
   agent can see what happened before it asked for control. (a) records
   less of the human's activity; (b) sees more. Recommendation: (a).
2. **Where does the buffer live?** The CLI exits after each command, so
   only the long-running MCP server can keep one. Recommendation: in the
   MCP server (a reader thread); the CLI gets no `events` subcommand —
   unlike every other tool, so this needs your agreement. The alternative
   is a separate user service, which is more to run and secure.
3. **Use it in the surface check?** Making `_refuse_new_surfaces` exact
   with `openlayer`/`closelayer` closes the leave-and-return gap, but
   touches the gate. In scope here, or a follow-up issue?
