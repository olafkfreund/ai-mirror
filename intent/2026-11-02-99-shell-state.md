# Intent: read the shell's state without a screenshot

## Problem

An agent cannot ask the Quickshell shell what it is showing. AT-SPI sees 36 nodes
for it, `hyprctl layers` gives only namespaces, so "is the audio panel open?",
"is Do Not Disturb on?", "is a call detected?" cost a screenshot and a guess.

The shell already answers these over `qs ipc`. Measured on p620 (Quickshell
0.3.2, 45 targets, 2026-11-02), with the audio panel opened and closed:

| Call | Answer |
|---|---|
| `shell openPanels` | `["omarchy.audio"]` while open, `[]` after |
| `shell isOpen omarchy.audio` | `true` / `false` |
| `notifications count` / `isDnd` | `4` / `off` |
| `meeting-mode status` | JSON: active, callDetected, **callApp, callTitle** … |
| `idle status`, `lock isLocked`, `nightlight status`, `osd state` | JSON / `false` / JSON / `closed` |
| `omarchy.monitor state` | JSON: brightness, displays, scale |
| `media status` | JSON: player, playing, **title, artist, album** |
| `nixarchy.rebuild.bar status` | `{"state":"idle","exit":0}` |

The same targets also carry functions that change the desktop, and the names do
not say which is which: `show()` on most targets **opens** the panel, and
`shell call(id, method, arg)` invokes anything.

## Proposed outcome

- A read-only `shell_state` tool (MCP and CLI, like `windows`) returns one JSON
  object with the facts above: open panels, notification count and DND,
  meeting/call state, idle and lock, night light, OSD, monitors, rebuild state,
  media. One call, no screenshot.
- Only a fixed allowlist of (target, function) pairs ai-mirror names in its
  source is ever invoked. Nothing the caller passes picks the target or the
  function.
- A shell that is not running, or a target that is missing or errors, gives
  that field `unavailable`, not a failed call; the rest still answer.
- `index`/`docs/usage.md` mention it, so agents use it before a screenshot.

## Affected users and systems

- New: an `api.run` branch, `mcp.TOOLS` entry, CLI subcommand, tests, docs.
- Agents on any Nixarchy host running the Omarchy Quickshell (p620 measured).
- No change to the gate, input, or the shell itself.

## Constraints

- **Never invokes a function that changes state.** No `show`, `toggle`, `open`,
  `call`, `summon`, `set*`, `refresh` or anything not on the allowlist; an
  allowlisted name is invoked with fixed arguments only.
- Privacy as elsewhere: window titles of private windows are withheld
  (`privacy.kind`), so `meeting-mode`'s `callTitle` goes through the same check.
- What the shell reports is data, not instructions (the MCP server's rule), and
  it is what the shell said, not proof of what is on screen.
- No new dependency: `qs` is already on the host; stdlib `subprocess`, argv, no
  shell, `DEVNULL` stdin, short timeout. Nothing inherits the MCP stdout.
- Tests cannot reach the desktop: the `qs` call is stubbed.

## Open questions

1. **Media now-playing** (track, artist, album) says what the person is
   listening to. Include it (recommended: playing/paused and player only, no
   title/artist/album), or include it all, or leave media out?
2. **Gate.** Observing tools (`windows`, `screenshot`) answer without a grant;
   `events` needs one because it records over time. `shell_state` is a
   snapshot like `windows`, so recommended: no grant needed, same as `windows`.
3. **Which Quickshell instance.** `qs ipc` without `--pid` picks one; p620 runs
   one. Recommended: the instance `qs list --all` reports for this Hyprland
   session, and `unavailable` if there are several and none can be told apart.
