# Plan: read the shell's state without a screenshot

## Approved decisions (self-contained)

- New read-only tool `shell_state`, MCP **and** CLI, no arguments, no grant
  (in `api.OBSERVING`, like `windows`).
- It invokes only the 11 fixed `(target, function)` pairs in `shell.READS`, with
  no arguments, via `qs ipc --pid <pid> call <target> <function>`. Nothing the
  caller passes reaches the argv. Never `show`/`open`/`toggle`/`call`/`summon`/
  `close`/`hide`/`refresh`/`set*` (on this shell `show()` opens a panel).
- Instance: the block in `qs list --all` (text, not `--json`: JSON has no display
  field) whose `Display connection:` is `wayland/$WAYLAND_DISPLAY`; exactly one →
  its `Process ID`, otherwise no instance.
- No instance → every field `'unavailable'` plus
  `note: 'no Quickshell instance on this display'`. One field failing (timeout,
  non-zero exit, empty output, `FileNotFoundError`, bad output) → that field
  `'unavailable'`, the rest answer.
- `media` → `{'player': <identity>, 'playing': <bool>}` only.
  `meeting` → as reported, `callTitle` replaced by `<withheld: KIND>` when
  `privacy.kind(callApp, callTitle)` returns KIND.
- stdlib only; `stdin=DEVNULL`, `capture_output=True`, `timeout=2`, argv list,
  no shell.
