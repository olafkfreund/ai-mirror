# Plan: `ai-mirror audit`

Self-contained. The spec and intent do not need opening.

## The approved decisions, carried over

- **CLI only. No `mcp.SPECS` entry.** A deliberate departure from AGENTS.md's
  *"api.run branch + mcp.TOOLS entry + CLI subcommand + test"*. The reader is
  a person deciding whether to trust what an agent did; offering the agent its
  own trail is a different feature, and AGENTS.md's own invariant — *"Do not
  add machinery claiming more"* — cuts against handing a trust artifact to the
  party being trusted. It still gets an `api.run` branch, because that is
  where the logic belongs and what the tests drive.
- **A test asserts the absence**, so the omission is a decision a future
  change must argue with rather than a gap somebody quietly fills.
- **AGENTS.md gains a sentence** naming the exception and why.
- **Read-only, structurally.** No clear, no rotate, nothing that could be
  mistaken for one. A log an agent can truncate is worse than no log, because
  it reads as evidence.
- **Last 20 by default, `-n` to change it.**
- **Human-readable by default, `--json` for the raw lines.** "JSON in/out" is
  the house style for the MCP surface, which this is not part of.
- **`status` names the verb**, so it is discoverable rather than merely
  present.
- **`absent` is distinguished from empty.** The whole second half of the
  issue: `$XDG_RUNTIME_DIR` does not survive a reboot, so "no entries" and
  "this machine rebooted since" must not look the same.

## Facts checked before planning, not assumed

- **`/proc/stat` has `btime`** on this machine (`1790073007`). It is the
  honest source for "when the log begins": the file's mtime is the time of the
  *last* write, not the first.
- **`Base.setUp` already isolates `XDG_RUNTIME_DIR`** into a
  `TemporaryDirectory`, so fixture audit lines cannot reach the real log and
  no new harness is needed.
- **`control.root()` creates its directory on every call**, so the directory
  always exists and only the *file* signals whether anything was recorded —
  which is what makes `absent` a clean answer rather than an error.
- **The event vocabulary is five names**, all written from `control.py`:
  `requested`, `confirmed`, `denied`, `expired`, `off`, `idle`.
- **Tests are unguarded for reads** (AGENTS.md), and this is a read, so
  nothing here needs `guard.disarm()`.

## Steps

1. `src/ai_mirror/control.py`: a `read_audit(limit)` returning
   `{'entries', 'source', 'total', 'skipped'}` — parsed lines newest last,
   `source` `'file'` or `'absent'`, malformed lines skipped and counted rather
   than fatal → verify by step 7's tests

2. Same file: `boot_time()` reading `btime` from `/proc/stat`, returning
   `None` when absent rather than raising. A missing `btime` degrades to
   omitting `since`, never to failing → verify by a test patching the read

3. `src/ai_mirror/api.py`: an `audit` branch in `run`, returning
   `{'entries', 'since', 'source', 'total'}`. **Not added to `OBSERVING`** —
   that list makes `by='agent'` calls mark the bar as watched, and there is no
   agent path here → verify `'audit' not in OBSERVING`

4. `src/ai_mirror/cli.py`: an `audit` subcommand with `-n` and `--json`. The
   human rendering is one line per entry, `at  event  k=v …`; the empty case
   says which empty it is and why, naming the boot time → verify by running it

5. `src/ai_mirror/api.py`: `status` gains a field naming the verb → verify it
   appears in `status` output and in the MCP one, which is acceptable because
   it is a pointer, not the trail

6. `AGENTS.md`: the sentence recording that this verb is CLI-only, and why →
   verify by reading it as someone about to "complete" the recipe

7. `tests/`: the cases in the table below, in the existing `Base` class so
   `XDG_RUNTIME_DIR` is isolated → verify by the suite

8. `python3 -m unittest discover -s tests` and `nix flake check` → verify
   green, and that the count went up by the number of new tests

## Tests

```sh
python3 -m unittest discover -s tests
nix flake check
nix build .#ai-mirror
ai-mirror audit          # on this machine, which has a real log
```

Baseline before any change: **170 tests, OK.**

| case | asserts |
|---|---|
| three known lines | parsed, newest last, fields intact |
| **no file** | `source == 'absent'` |
| **zero-byte file** | `source == 'file'`, `entries == []` — and *different* from the row above |
| good / truncated / good | two entries, `skipped == 1`, no exception |
| 50 lines, no `-n` | 20 returned |
| `-n 0` | everything (the spec's open question; if `--all` wins instead, this row changes) |
| **`'audit' not in mcp.SPECS`** | the omission is deliberate |
| `'audit' not in api.OBSERVING` | no agent path marks the bar |
| `status` names the verb | discoverable |
| `/proc/stat` without `btime` | `since` omitted, no raise |

**Prove each fails first (§1).** The ones that matter, because the others are
ordinary:

| break | must fail with |
|---|---|
| collapse `absent` and empty into one answer | the two rows above stop differing |
| let `json.loads` raise on a bad line | the truncated-line case |
| add an `mcp.SPECS['audit']` entry | the absence test, which is the point of having it |
| return oldest-last | the ordering assertion |

Revert with `git checkout HEAD -- <path>`, and commit a known-good baseline
before starting the loop.

## Rollback

Additive across five files plus tests. Reverting removes a read-only verb;
nothing that existed behaves differently, because `status` gains a field and
loses nothing, and no write path is touched at any point.

No state, no migration, nothing on disk changes shape — the log format is
unchanged and this only reads it.
