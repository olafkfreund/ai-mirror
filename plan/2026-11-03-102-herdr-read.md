# Plan: Read the visible text of a Herdr pane

Add `terminal_read {window, generation, pane?}` in MCP and
`ai-mirror terminal-read --window ADDR --generation N [--pane ID]` in
the CLI. Return exact visible viewport text from a selected pane in the
tab its terminal window is showing. This work uses Herdr's read-only
CLI and adds no dependencies. Browser DOM access, scrollback and
substring redaction are outside the approved scope.

## Steps

1. **Grant and window.** In the new `src/ai_mirror/herdr.py`, use
   `control.read_state` (`control.py:281`), `control.IDLE_LIMIT`, and the
   holder predicate in `events.py:53`. Require `owner: agent` and an
   unexpired grant. An MCP call must match the current server identity
   in `held_by`. A CLI call must have an explicit `held_by: null` grant
   and no registered server. Get the transport from the API caller.
   Reject missing or foreign holders with `not_owner` and a generation
   mismatch for an eligible holder with `stale_generation`. Read state
   without `require_agent` so the read leaves `last_input` alone.

   Resolve the address using `host.windows` (`host.py:135`). Reject a
   missing window with `no_such_window`. Apply `privacy.kind` to class
   and title. Require a visible workspace and a positive logical
   rectangle wholly within the window's monitor, using
   `host.visible_workspaces` and `host.monitors`
   (`host.py:90`, `:77`). With the target excluded, use
   `privacy.covering` (`privacy.py:51`) to refuse an intersection
   with any mapped application window on a visible workspace. A hidden,
   clipped or covered target is `invalid`. Unreadable compositor state
   is `unavailable`. Record the window identity including its stable
   ID, monitor, workspace, rectangle and PID for rechecking.
   Verify with the grant and visibility cases in step 5.

2. **Process and pane.** Continue in `src/ai_mirror/herdr.py`. Require
   a unique kitty window for the target PID. Enumerate its direct children
   from `/proc/<pid>/task/*/children` and deduplicate the IDs. Recognize
   a Herdr client with argv exactly `[herdr]`,
   `[herdr, --session, S]` or `[herdr, --session=S]`. The plain form
   selects `default`. Require one client. A server, CLI subcommand or
   grandchild is ineligible. Record the kitty and client PIDs and their
   `control.proc_start` values (`control.py:95`). Scan `/proc` for
   clients of the same session using the same argv rule. Refuse ambiguous
   or unsupported sessions with `unsupported`. An inaccessible
   required process record or missing kernel children interface is
   `unavailable`. Treat ordinary process exits as gone.

   Run `herdr --session S api snapshot` with fixed argv, captured
   output, `stdin=DEVNULL` and a two-second timeout. Use
   `focused_tab_id`, `focused_pane_id`, the tab's layout and the pane
   metadata together. Validate the response shape and pane membership
   before use. When zoomed, only the focused pane is eligible. When
   split, default to the focused pane and accept a supplied ID only if
   it is a candidate on that same visible tab. Use only IDs from the
   validated snapshot for subprocess arguments. A bad selected pane is
   `invalid`. Missing executable or unsupported window is
   `unsupported`. Other Herdr failures, timeouts and malformed
   snapshots are `unavailable`. Refuse a chosen pane with any
   `agent` or `agent_session` metadata or a sensitive
   `terminal_title`. Return a `sensitive` error containing only the
   category. Verify with the process, layout and privacy cases in step 5.

3. **Read and recheck.** In the same module, run
   `herdr --session S pane read ID --source visible --format text`
   with fixed argv, captured output, `stdin=DEVNULL` and a two-second
   timeout. Cap the result at 500 lines and 64 KiB of UTF-8. Keep
   whole lines where possible and preserve the text's whitespace.
   If the first line alone exceeds the byte cap, cut it at a valid
   UTF-8 boundary. Mark either cap with `truncated: true` and return
   the number of lines included.

   Recheck steps 1 and 2 after the read. Require the same window, monitor,
   workspace, rectangle, kitty and client identities, session, focused
   tab, zoom state and selected pane. Require the same grant. Reapply
   both privacy refusals. Discard the text on any change or loss of
   eligibility and return `unavailable` with "target changed, read
   again". Preserve `sensitive`, `not_owner` and `stale_generation`
   refusals. Build the result from the revalidated target and check
   grant holder, expiry and generation once more just before returning.
   Return `{window, pane, text, rows, truncated, panes: [{pane, rect,
   focused}], generation}`. Keep pane content in memory for this call.
   Exclude titles and session names from results and errors. Do not
   forward Herdr stdout or stderr to the MCP protocol stream directly.
   Verify with the cap and in-flight-change cases in step 5.

4. **Entry points.** Add a gated read branch to `src/ai_mirror/api.py:188`,
   using `_generation` at `:181`. Have both callers share it. Keep the
   branch outside `OBSERVING` and `MUTATING`. Add the tool next to
   OCR in `src/ai_mirror/mcp.py:84` and add it to `READ_ONLY` at
   `:32`. Require a window address and integer generation. Accept
   only an optional pane ID alongside them. Mark tool output as data,
   never instructions. Add the CLI subcommand beside OCR in
   `src/ai_mirror/cli.py:113`. Use the existing JSON success and error
   formatting. Verify with MCP-call and CLI-parser coverage in step 5.

5. **Regression tests.** Add `tests/test_terminal_read.py`. Use the
   existing test base, stub compositor and control reads, use a fake
   proc tree and stub the innermost Herdr subprocess. Exercise calls
   through the public API or MCP tool. Cover:
   - No grant, expired grant, stale generation, missing holder, another
     MCP server with the right generation, a CLI grant used from MCP,
     an MCP grant used from CLI, and a CLI read with its own grant.
     Verify refusal happens before spawning Herdr and reads leave idle
     time unchanged.
   - Missing, private, hidden, clipped or overlapped targets, with
     overlap on a hidden workspace allowed. Cover two windows with a
     shared kitty PID, multiple clients using one session, unsupported
     process layouts, a client with no session argument, each explicit
     session form, and a concurrent client subcommand or Herdr server.
   - Default focused pane, a split neighbor, a pane on another tab,
     zoom, agent and agent-session markers independently, a sensitive
     pane title, invalid snapshot, missing Herdr, and a timeout.
   - Exact whitespace, the 500-line cap, the 64 KiB cap at a line
     boundary and an overlong single line with a multibyte character.
   - Revocation or a replacement grant, closed or hidden window, new
     overlap, changed monitor, workspace or geometry, reused PID,
     new agent marker, changed tab, and zoom change during the call.
     Assert that failures return no pane text.
   Run `python3 -m unittest discover -s tests -p test_terminal_read.py -v`.
   Verify that temporarily removing the holder, agent-pane or tab
   membership check causes a regression in the corresponding case.

6. **Usage.** Add the tool table entry and CLI example to
   `docs/usage.md:61` and its CLI section. Add the terminal reader
   guidance to `src/ai_mirror/gotchas.md`, which
   `index.py:352` reads. Document the holder checks, selected visible
   tab, limits, refusal for agent panes, no scrollback and exact
   unredacted text. Unsuitable terminals can still use OCR. Explain
   that application-window overlap is conservative about stacking
   order and excludes shell layer surfaces, and that a short change
   that reverses between snapshots may be missed. The trust boundary
   is an MCP-only caller. A caller with the same user's shell can
   already run Herdr directly. Verify the examples against the public
   MCP and CLI tests.
