# Plan: Bounded confirmation that a prerequisite holds

## The approved decisions, carried

Implementable without opening the intent or the spec.

**What is built.** One read-only operation, `wait`, that polls Hyprland state
until a named prerequisite holds or a deadline passes. No event socket, no
threads, no module state, no cache.

**Why polling.** Measured on p620: every prerequisite is already a state query
costing ~10 ms (`layers`, `clients`, `activeworkspace`, `devices`). Events
cannot see a prerequisite that *already holds* — the commonest case — and would
add a subscription, a lifetime and an ordering race for nothing.

**Predicates, exactly one per call.** More than one makes failure ambiguous.

| Predicate | Holds when | Source and shape |
|---|---|---|
| `layer` | some layer has that namespace | `hyprctl layers -j` → `{mon: {levels: {lvl: [{namespace, …}]}}}` |
| `window_class` | some client has that class | `hyprctl clients -j` → `[{class, title, …}]` |
| `window_title` | some client's title contains it | same, substring match |
| `workspace` | active workspace has that id | `hyprctl activeworkspace -j` → `{id, monitor}` |
| `monitor` | that monitor is focused | `host.monitors()`, `focused` |
| `layout` | every keyboard reports that keymap | `hyprctl devices -j` → `{keyboards: [{active_keymap}]}` |

`absent: true` inverts, which is how a caller waits for a panel to *close*
before opening the next — the sequencing mistake that stacked panels during the
session behind #3.

**The loop.** Check once immediately, then every 50 ms to the deadline. The
immediate check is load-bearing, not an optimisation. Default timeout 3 s,
clamped to 30 s.

**Three results**, and keeping them distinct is the point:

```json
{"result": "confirmed",     "waited_ms": 210,  "polls": 5}
{"result": "not_confirmed", "waited_ms": 3000, "polls": 60}
{"result": "unavailable",   "reason": "Hyprland: ..."}
```

`not_confirmed` does **not** mean the action failed — a caller retrying on it
can toggle shut a panel that had just opened. `unavailable` means "could not
look", which is a different fact from "looked and it was not there".

**No control grant**, like `index`. A caller whose control was revoked already
fails on its next `input` with `not_owner`.

*(One wording slip to ignore: the approved spec's question 6 says "four
distinguishable outcomes" while its design section specifies three and explains
why. Three is correct — `cancelled` cannot occur in a synchronous call.)*

## Steps

1. `src/ai_mirror/wait.py`: new. One function per predicate returning a bool,
   a `PREDICATES` mapping, and `until(args)` running the bounded loop. Raises
   `ValueError` for an unknown or missing predicate; converts any `hyprctl`
   failure into `unavailable` rather than letting it surface as an error.
   → verify by `python3 -c "import sys; sys.path.insert(0,'src');
     from ai_mirror import wait; print(wait.until({'layer':'omarchy-background'}))"`
     returning `confirmed` on the first poll

2. `src/ai_mirror/api.py`: add `if op == 'wait': from . import wait; return
   wait.until(args)` among the read-only operations, above the `MUTATING`
   branch so no ownership gate applies.
   → verify by `ai-mirror wait --layer omarchy-background` with control off

3. `src/ai_mirror/cli.py`: `wait` subparser with `--layer`, `--window-class`,
   `--window-title`, `--workspace`, `--monitor`, `--layout`, `--absent`,
   `--timeout`. Prints JSON like every other operation.
   → verify by each flag returning a plausible result, and a bad combination
     being rejected

4. `src/ai_mirror/mcp.py`: add `wait` to `TOOLS` and to `READ_ONLY`. The
   description must state plainly that `not_confirmed` does not mean the action
   failed, because that is the misreading which makes this dangerous. Add one
   clause to `INSTRUCTIONS`: confirm a panel is up before typing into it.
   → verify by `tools/list` over stdio showing `wait` with `readOnlyHint` true

5. `src/ai_mirror/gotchas.md`: an entry for confirming before typing, naming
   `wait --layer` and `--absent`, and saying what `not_confirmed` does not mean.
   This is the file `index` serves, so it is how the habit reaches an agent.
   → verify by `ai-mirror index` containing it

6. `tests/test_invariants.py`: `hyprctl` stubbed. Each predicate true and
   false; `absent` inverts; an already-true prerequisite returns on the first
   poll; a never-true one returns `not_confirmed` at the deadline rather than
   raising; a failing `hyprctl` returns `unavailable` and never
   `not_confirmed`; an unknown predicate is rejected by name; no predicate at
   all is rejected; `timeout` is clamped; a prerequisite that becomes true
   part-way through is noticed within about one interval rather than at the
   deadline.
   → verify by `python3 -m unittest discover -s tests -v`

7. `tests/smoke.py`: live — press `SUPER + ALT + N`, `wait --layer
   nixarchy-pkg-menu` confirms in under a second; `omarchy-shell hide` then
   `--absent` confirms; `wait --layer does-not-exist --timeout 1` returns
   `not_confirmed` at its deadline. Restores control and closes the panel in a
   `finally`.
   → verify by running it in `nix develop` on this host

8. `AGENTS.md`: code-map row for `wait.py`, and a line in the desktop section
   that a panel should be confirmed before typing into it.
   → verify by reading the diff

9. `flake.nix`: no change expected — the install phase copies the package
   directory wholesale. Confirm rather than assume.
   → verify by `test -f "$(nix build .#ai-mirror --print-out-paths)/lib/ai_mirror/wait.py"`

## Tests

```sh
python3 -m unittest discover -s tests -v   # all pass, including the new cases
nix build .#ai-mirror .#ai-mirror-input .#plugin
nix flake check
ai-mirror wait --layer omarchy-background            # confirmed, one poll
ai-mirror wait --layer nope --timeout 1              # not_confirmed at ~1s
python3 tests/smoke.py                               # live; moves the mouse
```

Acceptance: drive the package-panel sequence with a `wait` between pressing the
key and typing, and then repeat it with a deliberately wrong keybinding. The
first confirms and proceeds; the second returns `not_confirmed` and the
sequence stops, instead of typing into whatever had focus. That second half is
the whole point — a test that only shows the happy path would not have caught
the failure this came from.

## Rollback

`git revert` the implementation commits. Nothing to undo beyond that: `wait`
holds no state, starts no service, writes no file and opens no socket. A caller
that had begun using it gets an unknown-operation error and is back to the
sleep-and-hope it does today.
