# Plan: a default that cannot reach your desktop

## The approved decisions, in full

Implementable without opening the intent or the spec.

**The problem.** Twice a test has been one forgotten stub away from writing to
the developer own session: #12 control gate, where `ControlTests` already takes
control and would have written `org.a11y.Status` on the real bus, and 584d8ee
before it, which fixed a test that wrote to the real desktop. Both were caught
by a person reading a diff. Nothing structural prevents a third. Separately,
#12 step 7 measurement of what `ScreenReaderEnabled` costs **failed** on this
host: two paired 40 s rounds disagreed, because Chrome sat near 72% of a core
with video playing, and the processes measured do not honour the property.

Decisions carried over:

1. The split is not by speed. The side-effecting seams **refuse to act while the
   suite runs**, so a forgotten stub is a test error, not a write to somebody
   desktop.
2. Reads stay allowed. Window queries and an AT-SPI walk observe without
   disturbing; `index.nav()` `enable=False` read must keep working. Guarding
   reads would force a mock in front of every harmless query.
3. Switching the guard off for a test that genuinely wants a live seam must be
   **one obvious line**. An awkward switch gets disabled globally and the guard
   becomes theatre.
4. No `devenv.nix`, and no NixOS VM test. The devShell already exists; the
   compositor test was the most speculative part and nothing depends on it.
   Virtual input, #11 confirm dialog and the kill switch therefore **stay
   uncovered**, by choice.
5. #12 step 7 measurement is in scope, taken in a headless throwaway VM, and its
   result written into #12 plan whatever it shows.

## Steps

**1. New `src/ai_mirror/guard.py`: one switch, off by default.**
A module flag, a `forbid()`/`allow()` pair for tests, and a `check(seam, stub)`
that raises a clear error naming the seam and what to stub. It is its own module
so no seam imports another, and so the switch has one home.
-> verify by a unit test: off by default, `check` raises only while armed, and
the message contains the seam name and the stub hint.

**2. Arm the seams.** Each calls `guard.check(...)` before acting:
- `a11y.set_bus_property` -- writes `org.a11y.Status`. **Needs #14.**
- `control.Helper.start` (`control.py:272`) and `.cmd` (`control.py:288`) -- the
  virtual keyboard and pointer.
- `host.ctl` (`host.py:10`) **only when `args[0] == "dispatch"`** -- moving the
  human windows. Queries are untouched, per decision 2.
-> verify by a test per seam: armed, each raises; unarmed, each still works.

**3. `tests/test_invariants.py`: `Base.setUp` arms it.**
One line plus `addCleanup`, next to the existing `XDG_RUNTIME_DIR` patch
(`tests/test_invariants.py:50-56`). A test that genuinely wants a live seam
disarms it in one line, per decision 3.
-> verify by the whole suite still passing.

**4. The sabotage check, as a committed script or a documented command.**
Remove the bus stub from `Base.setUp`, run the suite, and confirm it **fails
naming the seam** while the session bus property reads the same before and
after.
-> verify by doing it and recording both readings here. A guard that cannot
reproduce #12 near-miss on purpose is not doing anything.

**5. `AGENTS.md`: one invariant.**
Into `## Invariants -- do not break` (`AGENTS.md:41`): tests cannot reach the
desktop; the seams refuse while the suite runs; disarm in one line if a test
genuinely needs one. The `## Develop` section needs nothing -- see "Already
satisfied".
-> verify by reading it against what the code does.

**6. Finish #12 step 7, in the VM. Needs #14.**
A headless throwaway nixarchy VM reached over its forwarded ssh port. Install or
copy in `ai-mirror`, list what is running, then per round: set the property,
idle a fixed interval, sample CPU **per PID counting only PIDs alive at both
ends** -- the naive sum over matched process names reported **-147 s of CPU over
30 s** on the host, because Chrome renderer set changes between samples. Confirm
the property before and after each round, and reverse the order on the second.
-> verify by a number written into `plan/2026-09-20-12-a11y-enable.md` under
"Measured (step 7)", replacing the paragraph that says the cost is unmeasured --
**including if it still shows nothing**, and saying so explicitly if nothing in
the VM honours the property at all, rather than reporting a misleading zero.

## Tests

Enter the flake dev shell, run the unit suite and the flake checks. Expected:
green, including the new guard cases. The sandboxed run must stay green with no
compositor and no session bus.

Sabotage, expected to **fail**: delete the bus stub from `Base.setUp`, run the
suite, then `git checkout tests/test_invariants.py`.

## Rollback

`git revert` the implementation commits. `guard.py` is new and additive; the
seams gain one call each. Nothing outside the repository changes, except that
step 6 sets a property inside a throwaway VM whose disk is discarded at
shutdown -- the host bus is never touched by it.
