# Plan: `input` confirm — check that an input changed something

## Approved decisions (self-contained)

- **Where:** only `input` gets an optional `confirm` object (MCP schema, CLI
  `--confirm '<json>'`, `api.run`). `window` and `launch` already confirm their
  own effect.
- **Name:** `confirm`, because `a11y_act`'s `expect` is a precondition.
- **Predicates:** `confirm` holds exactly one of them, plus an optional `timeout`
  (default 3 s, max 30 s, through `wait._timeout`).

  | Predicate | Before the batch | Confirmed when |
  |---|---|---|
  | `wait.PREDICATES` keys (`layer`, `window_class`, `window_title`, `workspace`, `monitor`, `layout`), with optional `absent` | the predicate's bool `b0` | `check() is not absent` now **and** `b0 is absent` (it did not already hold) |
  | `focus_changed: true` | the `activewindow` address | the address differs |
  | `title_changed: "<address>"` | that window's title (`None` if not found) | the title differs from before, or the window is gone |

- **Already held:** if `b0` already satisfied the target, the result is
  `not_confirmed` with `held_before: true`, and there is no poll. Report it
  directly with `polls: 0, waited_ms: 0`.
- **Flow in `api.run`'s input branch:**
  1. validate `confirm` (`ValueError` before anything is sent);
  2. read the before-state; on an exception, keep the reason and **still send**;
  3. `control.run_batch` as today. If it raises, raise: no poll;
  4. poll with `wait.poll`; if the before-read failed, return `unavailable` with
     its reason;
  5. add `result['confirm'] = {result, polls, predicate, waited_ms[, reason][, held_before]}`.
- **Never** retry or resend. The MCP `screenshot=true` capture still follows
  `api.run`, so it comes after `confirm`, with no change to `call_tool`.

## Steps

     or `None` for `{}`.
   - `_title_of(address, budget)`: from `_clients(budget)`, the matching
     `c['title']`, or `None`.
   - `confirmation(spec) -> (name, before, changed)`:
     - validates (a dict, exactly one of `PREDICATES` ∪ {`focus_changed`,
       `title_changed`}, `focus_changed` must be `True`, `title_changed` a
       non-empty str, `absent` only with the `PREDICATES` kind);
     - `before(budget)` returns the before value;
     - `changed(b0)` returns `(held_before: bool, check(budget) -> bool)`.

   shape above (or inline it in `confirmation`, whichever is shorter). Keep
   `until` and `poll` untouched.
   → verify `python3 -m unittest discover -s tests` (unchanged count, all pass).
   Traps:
   - `_timeout` already rejects nan and negatives; reuse it.
   - Reads are not guarded (`guard`), so tests stub `host.ctl`, never disarm.
   - Messages should match `until`'s style ("confirm takes exactly one of …").
