## Approved decisions (self-contained)

- The installed shell (`nixarchy-omarchy-tree` `rp5i87d4…`) creates **one**
  `Loader` per enabled plugin whose `kinds` include `overlay`. It is active
  while `keepLoaded` is true (`shell/shell.qml:1301-1330`).
  - Our plugin is enabled through its `bar.layout` entry, so no new setting
    is needed.
  - The loader injects `omarchyPath`, `shell`, `manifest` and
    `pluginRegistry`, but not `settings`.
- `omarchy-plugin-validate` requires `entryPoints.overlay` for kind
  `overlay`.
- Declaring `overlay` changes the shell's `summon` routing; ai-mirror never
  uses `summon`.
- **Design:**
  - The manifest gains the `overlay` kind and entry point.
  - A new `plugin/Overlay.qml` owns the only `AgentConfirmDialog`, with its
    own state `FileView` and `AgentCommand`.
  - `Widget.qml` drops its dialog, and keeps the mark, tooltip, click and
    stop.
  - `AgentConfirmDialog.qml` is unchanged.
  - `flake.nix`'s plugin check gains the overlay rule.
- **Verify live:** one `omarchy-ai-mirror-confirm` layer per request on the
  three-monitor host.

## Steps

1. **`plugin/manifest.json`:**
   - `"kinds": ["bar-widget", "overlay"]`;
   - `"entryPoints": {"barWidget": "Widget.qml", "overlay": "Overlay.qml"}`.

   Nothing else changes. Keep `keepLoaded: true` and the 2-space style.
   - → verify: `jq . plugin/manifest.json`.
   - Traps: `id` must stay `olafkfreund.ai-mirror`, since the user's
     `shell.json` refers to it.

2. **`plugin/Overlay.qml` (new).**
   - Imports: `QtQuick`, `Quickshell`, `Quickshell.Io`. Root is an `Item`.
   - Accept the injected properties, so the loader's `"shell" in item`
     checks find them: `property var shell: null`, `property var manifest:
     null`, `property string omarchyPath: ""`.
   - `property var state: null`, and
     `readonly property bool pending: state !== null && state.owner ===
     "pending"`.
   - A `FileView` on `$XDG_RUNTIME_DIR/ai-mirror/state.json`, copied from
     `Widget.qml:53-61` (`watchChanges`, `printErrors: false`, `reload()`
     on change, `JSON.parse` in `try` → `null`, and `onLoadFailed` →
     `null`).
   - `AgentCommand { id: command }`.
   - `AgentConfirmDialog { request: root.pending ? root.state.request :
     null; command: command }`.
   - A header comment of 2–3 lines: why the dialog lives here (one per
     shell, #58), not in the per-bar widget.
   - → verify: step 6.
   - Traps:
     - No `qs.*` import is needed here; `AgentConfirmDialog` brings its own.
     - Copy the `FileView` exactly. A parse failure must give `null`,
       which #48's vanish-reset relies on.
     - *Corrected after review (critical): this step originally named only
       `Widget.qml:53-61`, missing the retry `Timer` at lines 62-68
       (`running: root.state === null; onTriggered: file.reload()`). The
       state file exists only after first use, so without the timer a shell
       started on a fresh login never sees a request. The dialog never
       appears, and every request lapses until the shell restarts. The
       timer is now copied, and `test_confirm_wiring.OverlayState` pins it
       (a mutation check confirmed that removing it fails the test).*

3. **`plugin/Widget.qml:30-33`: delete the `AgentConfirmDialog { … }`
   block.** Nothing else changes. Its `AgentCommand` (line 28) stays,
   because the widget's own click uses it.
   - → verify: `grep -c AgentConfirmDialog plugin/Widget.qml` gives 0.
   - Traps: don't touch the widget's state `FileView`. The mark still needs
