# Plan: one key press is one key, however slow the desktop

Approved decisions, carried over from the spec:

- A new helper command `P <code> [<code> ...]` (1-5 evdev codes) presses its
  codes in order and releases them in reverse, with one timestamp. Each
  event updates `key_state` and `keys_down` and sends the modifiers, as `K`
  does. Then one flush, one round trip, one `OK`. A bad code answers
  `ERR bad key` before anything is sent.
- The encoder emits `P c1 ... cn` for a `key` action, and `P 28` / `P 15`
  for a newline or tab inside `type`. `key_down`, `key_up` and the
  `modifiers` field stay `K` lines.
- `run_batch` is unchanged: it checks before every line, and it tracks
  holds only from `K ` and `B ` lines.
- Rejected: skipping checks on release lines, a Hyprland `device` repeat
  rule, equal timestamps.

## Steps

1. `src/ai_mirror_input/ai_mirror_input.c`:
   - Header comment (lines 7-15): after the `K` line, add
     `P <code> [<code>...]  tap: press in order, release in reverse, one flush (1-5 codes)`.
   - In the line handler, beside `op == 'K'` (around line 297): add
     `op == 'P'`. Parse up to 5 integers from `line + 1` with `strtol` and
     check each is `0..KEY_MAX`. With none, a bad one or more than 5, print
     `ERR bad key` and return before sending anything. Take one
     `t = now_ms()`. For each code in order: `zwp_virtual_keyboard_v1_key(kbd, t, code, 1)`,
     `keys_down[code] = true`, `xkb_state_update_key(... XKB_KEY_DOWN)`,
     `send_modifiers()`. Then in reverse: the same with 0, `false` and
     `XKB_KEY_UP`. Then `wl_display_flush`, `roundtrip_or_die()`, `OK`.

   → verify: `nix build .#ai-mirror-input` builds with no new warnings.

   Traps: exactly one ack line on every path. Do not round trip between
