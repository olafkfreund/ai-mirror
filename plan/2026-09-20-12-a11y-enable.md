# Plan: switch accessibility on properly, and say what it gives us

## The approved decisions, in full

Implementable without opening the intent or the spec.

**The problem.** `enable_bus()` (`a11y.py:29`) sets `org.a11y.Status IsEnabled`
and nothing else, and discards the `busctl` result. On this desktop that yields a
tree with no content: 24 nodes, maximum depth 1, roles only `frame` and
`application`; `a11y-find` for `push button`, `link` and `entry` all return `[]`.
Setting `ScreenReaderEnabled` as well, measured twice under an A/B, moved exactly
one application from absent to 129 nodes with buttons and links, while Chrome
stayed at 13, Discord at 2 and generic `electron` at 2. Separately,
`gotchas.md:89` tells every agent that "Electron and GTK applications do expose
full trees with bounds and actions", which is false here and is served on every
`index` call because `gotchas` is in `DEFAULT_SECTIONS` (`index.py:47`).

Decisions carried over:

1. `enable_bus()` sets **both** properties, reports a non-zero `busctl` exit
   instead of swallowing it, and returns what each property was beforehand.
2. Enablement happens at the control gate — `control.set_owner('agent', …)`
   (`control.py:86`) — not permanently. This keeps the cost off the human's
   desktop while no agent is driving, and gives toolkits time to build trees
   before the first `a11y_find` rather than racing it.
3. `set_owner('off', …)` restores **only what we changed**, from values recorded
   in `state.json`. A pre-existing `true` (a human running a real screen reader)
   is never written back to `false`.
4. `_walk` (`a11y.py:69`) keeps its `enable` parameter and its meaning, but the
   call becomes idempotent per process, so a `busctl` subprocess is paid once
   rather than on every `a11y_tree` and `a11y_find`.
5. `tree()` and `find()` report coverage — nodes visited, and whether anything
   below application/frame level was seen — computed from the traversal that
   already runs, with no extra AT-SPI calls. An empty `find` must name the
   desktop, not the element, when no content tree exists.
6. `gotchas.md:89` is replaced with what is true here plus the command that
   checks it. It does not grow: `index` reads it on every orientation.
7. The Chromium `--force-renderer-accessibility` launch flag is **out of scope**,
   filed as a follow-up and referenced from `gotchas.md`.
8. `intent/2026-09-17-3-desktop-index.md:68` and
   `spec/2026-09-17-3-desktop-index.md:98` are **not touched**. They repeat the
   same false sentence but are approved records of what was believed then.
9. The enablement cost is measured, and recorded here whatever it shows —
   including if it shows the gating in decision 2 was unnecessary.

## Steps

**1. `a11y.py:29` — `enable_bus()` sets both properties and reports failure.**
Read both `IsEnabled` and `ScreenReaderEnabled` via
`busctl --user get-property org.a11y.Bus /org/a11y/bus org.a11y.Status <prop>`,
then set each to true. Return the prior values as a dict. A non-zero exit or a
timeout raises `MirrorError('unavailable', …)` naming the property that failed;
today's `capture_output=True, timeout=5` and its silence go.
→ verify by a unit test asserting both writes are issued and a failing `busctl`
raises rather than returning.

**2. `control.py:86` — `set_owner` enables on `agent`, restores on `off`.**
Inside the existing `locked('control')` block: on `mode == 'agent'`, call
`enable_bus()` and store its returned prior values in the state dict under a new
key; on `mode == 'off'`, read that key and write back only properties recorded as
having been `false`, then clear it. `atomic_write_json` (`control.py:44`) already
makes the write safe for the bar's `FileView`.
→ verify by a unit test: `agent` → `off` with a recorded prior `true` issues **no**
restoring write; with a recorded prior `false` it issues exactly one.

**3. `a11y.py:69-75` — `_walk` pays `enable_bus()` once per process.**
Module-level flag set on first successful call; `enable=False` still skips it
entirely, so `index.nav()` (`index.py:296`) continues to turn nothing on.
→ verify by a unit test calling `tree()` twice with `enable=True` and asserting
one `busctl` invocation, plus an existing-behaviour test that `nav()` issues none.

**4. `a11y.py:98,113` — coverage on `tree()` and `find()`.**
Count nodes visited in the walk and track whether any yielded node had
`depth >= 2` or a role outside `application`/`frame`. Both return values gain that
summary; `find()`'s is what makes an empty `nodes` list legible. When nothing
below frame level was seen, the result carries an explicit sentence naming the
desktop as the cause and pointing at `screenshot`. `api.py:62-67` passes the
richer dict through unchanged.
→ verify by reading the emitted sentence, and a unit test that a frames-only tree
sets the flag while a tree with a button does not.

**5. `gotchas.md:89` — say what is true, and how to check it.**
Replace the one false sentence in the existing "QuickShell exposes no
accessibility tree" section. Keep the section's `**Do:**` shape. Name the check
(`a11y-find --role 'push button'`), say enablement is per-application, and
reference the follow-up from decision 7. Net line count must not increase.
→ verify by `ai-mirror index` containing the corrected text and by
`wc -l src/ai_mirror/gotchas.md` being no larger than before.

**6. Tests land with their steps, in `tests/test_invariants.py`.**
The suite is `unittest` (`flake.nix:98-101`). `busctl` is mocked; no test writes
to the real session bus — the repo has form here, `584d8ee` fixed a test that
wrote to the real desktop.
→ verify by `nix flake check`.

**7. Measure the cost (decision 9).**
CPU time of the Chrome and Discord process trees over a fixed idle interval with
`ScreenReaderEnabled` false, then true, same windows open. Record the numbers in
this file under a "Measured" heading, then restore the property.
→ verify by the numbers being written here. If they show the cost is negligible,
add a line saying decision 2's justification was wrong while leaving the gating in
place, and raise it at PR review rather than silently keeping the reasoning.

**8. Follow-up issue for decision 7.** Open it, referencing #12, covering the
Chromium launch flag and the fact that it means changing how Omarchy launches
browsers.
→ verify by the issue URL, linked from the PR.

## Step 10, forced by #11 landing mid-flight

#11 ("Control is a request a human answers, not a switch an agent throws")
merged to master while this branch was open, and it moved the gate this work
hooks into. `set_owner('agent')` no longer grants anything — it writes
`owner: 'pending'` and waits; only `confirm_request` -> `_answer(granted=True)`
grants control.

Step 2 as approved would therefore have switched accessibility on **when the
agent asked**, before the human answered — the precise thing #11 exists to stop.
The decision it came from is unchanged ("enablement happens at the control
gate"); the gate moved, so the code moved with it:

- `_answer(granted=True)` enables and records.
- All three routes back to `off` restore: `set_owner('off')`, a denied request,
  and a request that lapses unanswered in `read_state`.
- `set_owner('agent')` carries any existing record across `pending`. Without
  that, a re-request from a live grant would drop it, the confirm would record
  the values we set ourselves, and `off` would restore nothing — the step 9 leak
  in a new shape.

→ verified by two added cases: asking alone writes nothing to the bus, and a
denied request puts back a live grant.

## Step 9, added during implementation

The plan kept `_walk`'s fallback enable (step 3) and never said what puts it
back. The runtime check in Tests found the consequence: a bare `a11y-find` with
control off switched `ScreenReaderEnabled` on permanently, so the very next
`control agent` recorded it as the prior value and `control off` left it on. One
read defeated decision 2 entirely.

`a11y.ensure_enabled()` now records what it switched on, and `release_bus()` puts
it back from the `finally` blocks that already exist in `cli.py:99` and
`mcp.py:246` for the input helper. It skips while an agent holds control, since
that grant has its own lifecycle. This fills a gap rather than changing an
approved decision: the spec said keep the fallback, not leak it.
→ verified by the Tests sequence below, which now leaves the bus as it found it.

## Measured (step 7)

CPU of each process tree over a 40 s interval, sampled per PID and counting only
PIDs alive at both ends. The first attempt summed over `pgrep` output at each end
and produced negative CPU, because Chrome's renderer set changes between samples.

| round | order | chrome | Discord | qemu |
|---|---|---|---|---|
| 1 | off then on | 28.99 -> 31.98 s | 1.34 -> 2.33 s | 7.17 -> 7.49 s |
| 2 | on then off | 29.37 <- 29.40 s | 1.34 <- 1.31 s | 6.88 <- 6.09 s |

**No measurable cost.** Round 1 suggested one; round 2, with the order reversed,
did not reproduce it for either Chrome or Discord. The desktop was in use
throughout — Chrome sat near 72% of a core with video playing — so round 1's
difference is drift.

### Attempted again in a VM (#15 step 6) — still unmeasured, for a new reason

The retry ran on a quiet host: zero CI jobs, load 6.5 on a 128-core box, the VM
prebuilt so its build could not compete with the measurement. It did not fail on
noise this time. It could not run at all:

```
busctl --user get-property org.a11y.Bus /org/a11y/bus org.a11y.Status IsEnabled
-> Failed to get property IsEnabled ...: The name is not activatable
```

**The stock nixarchy `.#vm` has no accessibility bus**, so the property this
decision is about does not exist there to set. The guest is otherwise a real
desktop — Hyprland 0.56 and quickshell running, `wayland-1` present,
chromium/nautilus/foot installed — and `at-spi2-core` is in its store as a
transitive dependency. What is missing is the D-Bus service file: no
`org.a11y.Bus` entry under the system's dbus services, so nothing can start the
launcher. On the host it is registered and live, so this is a NixOS option the
VM config does not carry rather than a missing package.

Reported rather than worked around, because the alternative was to report a zero
that meant nothing. Measuring this needs a guest with at-spi enabled first;
until then the paragraph below stands unchanged.

**Decision 2's justification is not supported by this measurement, and step 7
requires saying so.** The gating stays, for two reasons that survive: it removes
a `busctl` subprocess from every a11y call, and it gives toolkits time to wake
before the first `a11y_find`. But "keeps the cost off the human's desktop" is now
an unevidenced claim and should not be repeated as if measured.

The measurement was also badly targeted, which is worth more than its result:
Chrome and Discord do not honour `ScreenReaderEnabled` at all — both report
`content: false` either way — so they were the wrong processes to measure for its
cost. `qemu` exposes a tree regardless of the property. The one application
observed to respond was not running at measurement time. A targeted measurement
needs a process known to honour the property, and is worth doing before anyone
cites a cost here. Raised at PR review rather than settled silently.

## Rollback

`git revert` the implementation commits. The only state outside the repo is the
two `org.a11y.Status` properties, restored with:

```
busctl --user set-property org.a11y.Bus /org/a11y/bus org.a11y.Status ScreenReaderEnabled b false
```

`IsEnabled` was already `true` before this work and should be left `true`. No
application is restarted at any point, so nothing else needs undoing.
