# Plan: prune the window, keep the fact, never the name

## The approved decisions, in full

Implementable without opening the intent or the spec.

**The problem.** #19 stopped `screenshot` capturing a rectangle containing a
password manager or a credential prompt. `a11y_tree` and `a11y_find` have no
guard, and the exposure is worse: `_node()` (`a11y.py:116`) returns a role, a
name, bounds, the available actions and up to 120 characters of text per node,
and `a11y_act` can then act on what it found. That is a labelled, addressable
description of a passphrase field rather than a photograph of one.

Decisions carried over:

1. **A refused window is yielded with no name, a `withheld` category, and no
   children.** Dropping it hides that a window exists and reintroduces the
   absent-versus-unavailable confusion #18 fixed. Keeping the name exposes the
   sensitive part: frame names here carry an inbox count and an email address.
2. **Both levels.** An application whose own name matches (`1Password`,
   `gcr-prompter`) is pruned whole; a frame inside an ordinary application (a
   bank in Chrome) is pruned alone. Application-only is an **outage** — one
   `Google Chrome` node carries a frame per window, six here. Frame-only is a
   hole.
3. **`privacy.kind()` is reused unchanged.** Measured: an application node's
   `name` plays the part of a window class and a frame's `name` plays the part
   of a title, and the matcher answers correctly for a password manager, a
   banking title and a credential prompt.
4. **`find` says when it withheld something.** "No match" and "no match, and one
   window was not looked at" are different facts, and the second changes what an
   agent does next.
5. **`act` re-checks on resolve**, or the guard is bypassable with an id
   obtained just before a window became sensitive.
6. **`index.nav()` needs no special handling** — it calls `tree(None, 1, 200,
   enable=False)` (`index.py:306`) and inherits the frame guard.
7. **Cost, measured:** 11 applications and 16 frames against a walk yielding 154
   nodes — 27 extra `get_name` calls, where `_node()` already fetches five
   things per node. Under 5%, and nothing at the depths where the nodes are.

## Steps

**1. `a11y.py` — the AT-SPI mapping onto `privacy.kind`.**
`_withheld(acc, level, app_name) -> str | None`: at level 0 test
`kind(name, '')`, at level 1 test `kind(app_name, name)`, otherwise None. One
`get_name` per application and per frame, none deeper.
→ verify by a unit test: an application named `1Password` is caught at level 0,
a frame named `Revolut - Payments` under `Google Chrome` at level 1, an ordinary
pair is not, and nothing is asked at level 2.

**2. `a11y.py:143` — `_walk` tracks the application, yields the verdict, and
does not descend.**
It already tracks a root per iteration; it gains the root's name and yields a
fifth element. When that is set, the children loop is skipped. All three
consumers are in this file, so the contract change is internal.
→ verify by a unit test over a fabricated desktop: the refused frame is yielded,
its children are not, **and its sibling frames in the same application are
walked in full** — that is the Chrome case and the one that would be an outage.

**3. `a11y.py:196` — `tree()` renders a refused node without its name.**
`{"id": …, "role": "frame", "withheld": "<category>"}`. No `name`, no `text`, no
`bounds`, because `_node()` is not called for it at all.
→ verify by a test asserting the rendered node carries the category and carries
no `name` key.

**4. `a11y.py:213` — `find()` skips them and says so.**
A withheld node never matches. The coverage dict gains a withheld count, and the
note distinguishes "one window was not looked at" from #18's "this desktop
exposes nothing".
→ verify by a test: a find that would have matched inside a refused frame
returns nothing, reports the count, and its note differs from #18's.

**5. `a11y.py:268` — `resolve()` re-checks.**
It walks the index path from the desktop, so at parts 0 and 1 it applies the
same check and raises rather than returning an accessible inside a refused
window.
→ verify by a test that `act` on such an id raises, and that an ordinary id
still resolves.

**6. `gotchas.md` — one sentence beside #19's entry.**
A reader who learns captures are refused but not that trees are would reach for
`a11y_find` as the way round, which is the opposite of the intent.
→ verify by `ai-mirror index` containing it.

## Tests

```
nix develop -c python3 -m unittest discover -s tests -v
nix flake check
```

Expected green. New test classes inherit `Base`, which arms the guard and
isolates `XDG_RUNTIME_DIR` — a bare `TestCase` here is how a test reaches the
real desktop, and #21 shipped a fix for exactly that mistake.

## Rollback

`git revert` the implementation commits. The change is additive: one helper, one
extra element in an internal yield, and one check in `resolve`. No tool gains or
loses a parameter, and a desktop with nothing sensitive on it produces the same
output as before.
